# Kitab Bahasa Visual NexaMOS

**Versi:** 1.0\
**Status:** Baseline Kanonis / Sumber Memori Agent\
**Merek:** NexaMOS\
**Jenis Dokumen:** Identitas Visual, Ilustrasi Editorial & Sistem Generasi Gambar AI\
**Penggunaan Utama:** Blog NexaMOS, Google Discover, aset editorial website, media sosial, komunikasi produk, generasi gambar AI, dan implementasi coding-agent.

------------------------------------------------------------------------

## 0. Tujuan Dokumen Ini

This document is the canonical visual-language specification for
NexaMOS.

Tujuannya bukan sekadar mendefinisikan warna merek. It defines a reusable
visual system that allows humans, designers, developers, and AI agents
to create images that belong to the same NexaMOS visual universe.

Sistem ini harus tetap dapat dikenali pada berbagai topik seperti:

-   Marketing
-   CRM
-   Customer lifecycle
-   Market intelligence
-   Competitive strategy
-   Customer behavior
-   Advertising
-   Meta CAPI and server-side conversion
-   Data
-   Automation
-   Artificial intelligence
-   Marketing analytics
-   Decision systems
-   Growth
-   NexaMOS product and technology

Tujuannya adalah:

> A person should eventually be able to see a NexaMOS editorial image
> without seeing the logo and still recognize that it belongs to
> NexaMOS.

Dokumen ini merupakan sumber instruksi. AI/coding agents implementing
NexaMOS visual assets MUST treat the rules marked **LOCKED** or **MUST**
as constraints, not suggestions.

# 1. Filosofi Visual Inti

## 1.1 Ide Inti --- TERKUNCI

Ide visual utama NexaMOS adalah:

> **Membuat sistem pemasaran yang tak terlihat menjadi terlihat.**

Sebagian besar mekanisme pemasaran tidak terlihat: signals, intent, relationships,
decisions, customer states, data flows, intelligence, feedback, and
behavioral changes cannot normally be seen.

NexaMOS visual language turns these invisible mechanisms into visible
systems.

Karena itu, visual NexaMOS SEBAIKNYA memvisualisasikan:

**Market → Signal → Data → Pattern → Intelligence → Decision → Action →
Response → Learning**

rather than relying on generic representations such as businesspeople
looking at laptops.

------------------------------------------------------------------------

## 1.2 NexaMOS Adalah Sebuah Sistem, Bukan Sekadar CRM

Aset visual TIDAK BOLEH mereduksi NexaMOS menjadi:

-   a contact database;
-   a sales dashboard;
-   WhatsApp automation;
-   a generic SaaS interface;
-   a lead-management application.

Secara konseptual NexaMOS adalah **Marketing Operating System**.

The visual language therefore needs to represent an interconnected
system of:

-   market observation;
-   customer identity;
-   signals;
-   lifecycle states;
-   relationships;
-   intelligence;
-   strategy;
-   decisions;
-   execution;
-   conversion;
-   feedback;
-   learning.

------------------------------------------------------------------------

# 2. DNA Visual

Arah seni default NexaMOS adalah:

> **Futuristic editorial technology illustration + abstract data
> visualization + subtle dimensional/3D depth.**

Karakter visual yang diinginkan adalah:

-   intelligent;
-   systematic;
-   technological;
-   premium;
-   precise;
-   contemporary;
-   editorial rather than promotional;
-   sophisticated without becoming visually noisy.

NexaMOS SHOULD feel like a marketing intelligence system rather than a
generic software advertisement.

------------------------------------------------------------------------

# 3. Metafora Visual Inti: Closed Loop

## 3.1 Warisan Spiral

Logo NexaMOS memiliki struktur spiral/sirkular.

Bentuk ini bukan sekadar ornamen logo. It is a conceptual source for
the broader visual language.

Spiral dapat merepresentasikan:

-   continuous observation;
-   feedback;
-   learning;
-   iteration;
-   customer progression;
-   system intelligence;
-   market response;
-   optimization.

Loop konseptualnya adalah:

**OBSERVE → SIGNAL → INTELLIGENCE → DECISION → ACTION → MARKET RESPONSE
→ OBSERVE**

Ini sesuai dengan arsitektur closed-loop marketing NexaMOS.

------------------------------------------------------------------------

## 3.2 Geometri Sirkular --- TERKUNCI

NexaMOS illustrations MAY repeatedly use subtle derivatives of the
spiral through:

-   concentric rings;
-   orbit structures;
-   circular pathways;
-   curved data streams;
-   feedback loops;
-   radial networks;
-   circular processing layers;
-   spiral movement.

JANGAN menempelkan logo NexaMOS pada setiap ilustrasi.

The visual identity should be expressed through **geometry and
behavior**, not repetitive logo placement.

# 5. Sistem Node Entitas

## 5.1 Node sebagai Primitif Entitas Utama

NexaMOS does not need to represent every customer as a photograph of a
person.

A **node** is the preferred abstract representation for:

-   customer;
-   lead;
-   prospect;
-   audience member;
-   account;
-   organization;
-   market actor.

Nodes can change visual states to communicate lifecycle progression.

Example:

`UNKNOWN → KNOWN PROFILE → LEAD → PROSPECT → OPPORTUNITY → CUSTOMER`

The state change can be represented using:

-   clarity;
-   size;
-   illumination;
-   connectivity;
-   ring structure;
-   position;
-   movement;
-   semantic Nexa color intensity.

Avoid creating a completely different icon for every lifecycle state
when state transformation of the same entity can communicate the concept
more elegantly.

# 6. Arsitektur Warna

## 6.1 Fondasi Merek

The current NexaMOS logo establishes the principal visual family:

-   green;
-   teal;
-   cyan/blue-teal;
-   black;
-   white.

Approximate working palette derived from the current logo:

  Token              Approx. HEX Semantic Role
  ---------------- ------------- -----------------------------------------
  Nexa Green           `#00D690` growth, conversion, successful action
  Nexa Teal            `#04B394` relationship, customer, connected state
  Nexa Cyan/Teal       `#03A0A7` data, intelligence, technology
  Nexa Black           `#000000` system/environment
  Nexa White           `#FFFFFF` clarity, information, contrast

**Important:** These HEX values are the v1.0 working palette based on
the supplied logo. If official source/vector brand values are later
established, those official values supersede approximations in this
document.

------------------------------------------------------------------------

## 6.2 Gradient Khas --- TERKUNCI

The principal NexaMOS visual gradient is approximately:

`#00D690 → #04B394 → #03A0A7`

Conceptually:

**GREEN → TEAL → CYAN**

The gradient is not merely decorative.

It SHOULD primarily represent:

-   information in motion;
-   signals;
-   intelligence;
-   state progression;
-   active system behavior;
-   decision flow;
-   conversion flow;
-   computational activity.

Do not apply the gradient randomly to every object.

------------------------------------------------------------------------

## 6.3 Lingkungan Hitam

Dark/black environments are the default signature canvas for major
NexaMOS editorial illustrations.

Preferred behavior:

-   deep black or near-black environment;
-   bright semantic Nexa gradient;
-   selective glow;
-   high contrast;
-   controlled negative space.

Black represents the system/environment in which information becomes
visible.

This also creates strong continuity with the current NexaMOS logo.

------------------------------------------------------------------------

## 6.4 Putih

White primarily represents:

-   clarity;
-   readable information;
-   neutral/high-confidence state;
-   separation;
-   interface/editorial contrast.

White should support the visual hierarchy rather than overpower the
signature Nexa gradient.

------------------------------------------------------------------------

# 7. Prinsip Warna Semantik

Warna WAJIB memiliki makna.

Default semantic direction:

-   **Green:** action, growth, successful progression, conversion.
-   **Teal:** relationship, customer connection, active entity.
-   **Cyan/blue-teal:** data, intelligence, computation, technology.
-   **Black:** system/environment.
-   **White:** clarity/information.

If additional warning/error colors are required in actual UI products,
they may follow product UI semantics. However, editorial illustrations
should remain dominated by the NexaMOS core palette.

# 8. Sistem Komposisi

## 8.1 Satu Gambar = Satu Ide --- TERKUNCI

Setiap hero image editorial WAJIB mengomunikasikan satu konsep dominan.

Jangan mencoba memvisualisasikan seluruh isi artikel sekaligus.

For example, an article about Meta CAPI should not contain:

-   a phone;
-   a laptop;
-   Facebook logo;
-   Instagram logo;
-   CRM dashboard;
-   salesperson;
-   customer;
-   charts;
-   server rack;
-   shopping cart;

all competing for attention.

Sebaliknya, pilih satu mekanisme konseptual dominan, misalnya:

> **offline conversion returning as a data signal into the advertising
> system.**

------------------------------------------------------------------------

## 8.2 Komposisi Hero Default

Preferred structure:

-   one dominant conceptual object/mechanism;
-   supporting nodes or signals;
-   clear visual hierarchy;
-   substantial negative space;
-   strong silhouette;
-   readable at thumbnail size.

Typical conceptual layout:

``` text
+------------------------------------------------+
|                                                |
|          NEGATIVE SPACE                        |
|                                                |
|                        o                       |
|                   o -- O -- o                  |
|                      HERO                      |
|                   o -- o -- o                  |
|                         \                      |
|                          SIGNAL                |
|                                                |
+------------------------------------------------+
```

Ini bukan template literal. Ini merepresentasikan hierarki.

# 9. Aturan Gambar Editorial Google Discover

NexaMOS blog imagery is designed partly for Google Discover
distribution.

Therefore:

-   hero images SHOULD be large and high-resolution;
-   target width SHOULD be at least 1200 px;
-   preferred working master size is **1536 × 864 px (16:9)** unless
    another channel requires a different crop;
-   the main subject must remain understandable when reduced to
    thumbnail size;
-   avoid tiny critical details;
-   avoid excessive text embedded inside images;
-   avoid clickbait imagery unrelated to article content;
-   image subject MUST materially relate to the article;
-   images MUST NOT misrepresent what the article contains.

Website implementation should permit large image previews where
appropriate, including support for `max-image-preview:large`.

Discover eligibility is not guaranteed by image design alone. Visual
language is one component of the broader editorial, technical SEO,
content-quality, authority, and audience strategy.

# 10. Representasi Manusia

Manusia bersifat opsional, bukan default.

Gunakan manusia hanya ketika konsep artikel benar-benar berkaitan dengan:

-   human behavior;
-   decision psychology;
-   sales interaction;
-   organizational dynamics;
-   customer experience;
-   social influence.

Jika manusia tidak diperlukan, prioritaskan abstraksi sistem.

Avoid default SaaS clichés such as:

-   smiling employee holding a laptop;
-   team pointing at a dashboard;
-   handshake;
-   generic call-center employee;
-   businessman standing beside charts;
-   person touching a floating holographic interface.

------------------------------------------------------------------------

# 11. Representasi Kecerdasan Buatan

## 11.1 AI adalah Lapisan Komputasional --- TERKUNCI

AI secara umum harus direpresentasikan sebagai:

-   computational mesh;
-   pattern-recognition layer;
-   processing field;
-   connected inference network;
-   intelligent transformation layer;
-   emerging structure from data.

Avoid:

-   humanoid robots;
-   robot heads;
-   glowing AI brains;
-   android hands touching human hands;
-   generic circuit-board brains;

unless an article specifically discusses those cultural representations.

NexaMOS views AI primarily as a **computational capability inside a
marketing system**, not as a robot character.

------------------------------------------------------------------------

# 12. Representasi CRM

CRM SEBAIKNYA direpresentasikan sebagai:

> **a relationship and state network around identifiable customers.**

Preferred concepts include:

-   entity networks;
-   lifecycle progression;
-   interaction history;
-   connected identity;
-   state changes;
-   relationship paths;
-   customer-centered information structures.

Hindari mereduksi visual CRM menjadi spreadsheet atau buku alamat.

------------------------------------------------------------------------

# 13. Representasi Marketing Intelligence

Marketing intelligence harus mengomunikasikan transformasi secara visual:

`SIGNALS → PATTERN → ANALYSIS → INTELLIGENCE`

A strong NexaMOS intelligence visual can begin with many fragmented
signals and resolve them into:

-   an organized pattern;
-   a structured object;
-   a selected path;
-   a coherent network;
-   a clear decision input.

This expresses the difference between raw data and usable intelligence.

------------------------------------------------------------------------

# 14. Representasi Strategi

Strategi adalah tentang **pilihan**.

Preferred visual metaphors:

-   multiple paths with one selected;
-   constrained pathways;
-   branching system;
-   chosen territory;
-   gate;
-   trade-off;
-   resource concentration;
-   positioning within a competitive landscape.

Hindari penggunaan bidak catur secara otomatis pada setiap artikel strategi. Chess
is a generic strategy cliché and does not belong to the core NexaMOS
grammar.

------------------------------------------------------------------------

# 15. Representasi Customer Lifecycle

Canonical lifecycle currently used in the broader NexaMOS conceptual
system:

`UNKNOWN/AUDIENCE → KNOWN PROFILE → LEAD → PROSPECT → OPPORTUNITY → CUSTOMER → LOYAL/ADVOCATE`

Illustrations can visualize progression through:

-   increased node definition;
-   increased connectivity;
-   movement through filters;
-   crossing gates;
-   state illumination;
-   stronger Nexa gradient;
-   transition from peripheral to integrated system state.

Lifecycle imagery SHOULD communicate **state transition**, not merely a
row of disconnected icons.

------------------------------------------------------------------------

Bahkan gambar statis harus memberi kesan gerak.

Preferred movement:

-   inward signal flow;

# 17. Pencahayaan dan Material

Preferred:

-   controlled luminous edges;
-   subtle glow;
-   dimensional depth;
-   translucent or semi-translucent information layers;
-   refined digital materials;
-   high contrast;
-   precise reflections where useful;
-   dark environmental depth.

Avoid:

-   excessive neon;
-   cyberpunk city aesthetics;
-   gaming aesthetics;
-   rainbow lighting;
-   heavy lens flare;
-   overly glossy toy-like 3D;
-   cheap plastic rendering.

Targetnya adalah **teknologi editorial**, bukan hiburan sci-fi.

------------------------------------------------------------------------

# 18. Tipografi di Dalam Gambar

Aturan default:

> **Hero illustrations SHOULD NOT depend on text embedded inside the
> generated image.**

Reasons:

-   AI-generated typography is unreliable;
-   Discover thumbnails reduce readability;
-   article headline already exists outside the image;
-   text can make assets look like advertisements.

If typography is required, it should preferably be added
programmatically or in a design tool after image generation.

Pertahankan gambar dan headline sebagai layer yang saling melengkapi.

------------------------------------------------------------------------

# 19. Penggunaan Logo

Logo NexaMOS TIDAK wajib ada pada setiap hero image blog.

Pengenalan merek terutama harus muncul melalui:

-   color;
-   geometry;
-   composition;
-   primitives;
-   art direction;
-   recurring system metaphors.

If logo placement is necessary for social distribution or a campaign
asset, use the official logo separately from the AI-generated scene.

Do not ask an image model to redraw or invent the NexaMOS logo when the
authentic asset can be composited afterward.

------------------------------------------------------------------------

# 20. Aturan Negatif / Anti-Pattern --- TERKUNCI

NexaMOS editorial images should generally avoid:

-   generic stock-photo aesthetics;
-   humanoid AI robots;
-   robot heads;
-   glowing brains as default AI metaphor;
-   random dashboards;
-   fake software UI;
-   random financial charts;
-   excessive floating icons;
-   generic business handshakes;
-   generic office meetings;
-   cyberpunk city scenes;
-   rainbow neon;
-   unrelated futuristic objects;
-   excessive text;
-   visual clutter;
-   decorative gradients with no semantic purpose;
-   giant brand logo as substitute for an idea;
-   direct imitation of another brand's signature visual identity.

The image must communicate the **mechanism or idea of the article**, not
merely its industry category.

# 21. Kerangka Translasi Artikel ke Visual

Sebelum menghasilkan gambar, agent WAJIB mengidentifikasi:

1.  **Article subject**
2.  **Single dominant idea**
3.  **System mechanism involved**
4.  **Relevant NexaMOS primitives**
5.  **State/movement**
6.  **Semantic colors**
7.  **Hero object**
8.  **Supporting elements**
9.  **What must be excluded**

Example:

### Article

"Lead Bukan Sekadar Nomor WhatsApp"

### Dominant idea

A contact only becomes meaningful as a lead when identity and verified
interest exist.

### Visual primitives

-   anonymous particles;
-   identity node;
-   signal;
-   activation;
-   relationship network.

### Visual story

Many anonymous particles exist outside the system. One becomes clearly
identified, emits a verified signal, and becomes an active connected
node.

### Avoid

-   WhatsApp screenshots;
-   people holding phones;
-   giant WhatsApp logo;
-   contact lists.

# 22. Contoh Perlakuan Visual

## 22.1 What Is a Lead?

Concept:

`UNKNOWN → IDENTITY → VERIFIED SIGNAL → LEAD`

Visual: A field of anonymous dim nodes. One node becomes defined and
illuminated as identity and signal converge.

------------------------------------------------------------------------

## 22.2 Lead vs Prospect

Concept:

`LEAD → QUALIFICATION FILTER → PROSPECT`

Visual: An active node passes through a structured filtering layer while
other nodes remain outside.

------------------------------------------------------------------------

## 22.3 Opportunity

Concept:

`PROSPECT → COMMITMENT GATE → OPPORTUNITY`

Visual: A qualified node crosses a meaningful gate and enters an active
decision environment.

------------------------------------------------------------------------

## 22.4 Customer Journey

Concept: One persistent entity changes states through an interconnected
journey.

Visual: One node moves through multiple connected system states rather
than displaying unrelated customer icons.

------------------------------------------------------------------------

## 22.5 Meta CAPI / Offline Conversion Feedback

Concept:

`ADVERTISING → CUSTOMER → CRM → OFFLINE CONVERSION → SERVER SIGNAL → ADVERTISING`

Visual: A closed-loop system where a conversion occurring inside the
CRM/real-world transaction layer generates a structured signal that
returns into the advertising ecosystem.

The dominant metaphor is the **feedback loop**, not the Meta logo.

------------------------------------------------------------------------

## 22.6 Marketing Intelligence

Concept:

`MANY SIGNALS → PATTERN → INTELLIGENCE`

Visual: A large number of fragmented signals converge and reveal an
organized pattern.

------------------------------------------------------------------------

## 22.7 AI in CRM

Concept:

`CUSTOMER DATA + SIGNALS → COMPUTATIONAL LAYER → DECISION SUPPORT`

Visual: A computational mesh processes relationship signals and resolves
them into structured decision outputs.

No robot required.

------------------------------------------------------------------------

## 22.8 Strategy

Concept:

`POSSIBILITIES → CHOICE → CONCENTRATED PATH`

Visual: Several possible paths exist, but the system deliberately
selects and strengthens one.

article.

``` text
dark/deep-black environment,

controlled supporting elements,

strong thumbnail readability,
premium technology editorial aesthetic,
16:9 composition.

The Nexa gradient represents active information, intelligence,
progression, decision, or conversion rather than decoration.

Use circular/spiral-derived geometry subtly when feedback,
learning, iteration, or system behavior is relevant.

No embedded headline.
No fake dashboard.
No generic office workers.
No humanoid robot.
No glowing AI brain.
No random financial chart.
No cyberpunk city.
No rainbow neon.
No excessive icons.
No visual clutter.

```

This is a base architecture. The conceptual scene MUST be customized to
the article.

# 26. Uji Konsistensi

Sebelum menyetujui aset, tanyakan:

### Brand Test

Would this image plausibly belong to NexaMOS without showing the logo?

### Concept Test

Can the dominant mechanism be understood without reading a paragraph?

### Thumbnail Test

Does the hero concept survive at small size?

### Semantic Test

Are colors and primitives being used meaningfully?

### Clutter Test

Can at least one unnecessary object be removed?

### Generic-AI Test

Does the image look like a generic "AI technology" stock image?

Jika ya, tolak/perbaiki.

### System Test

Does the image represent relationships, signals, states, decisions, or
flows in a way consistent with NexaMOS?

# 27. Gerbang Kualitas Visual

An image is approved only if it satisfies the majority of the following
and violates none of the locked negative rules:

-   clear dominant idea;
-   strong hierarchy;
-   NexaMOS palette;
-   appropriate system metaphor;
-   strong dark/light contrast;
-   controlled glow;
-   premium editorial quality;
-   meaningful movement;
-   thumbnail readability;
-   minimal clutter;
-   semantic use of primitives;
-   visual continuity with other NexaMOS assets.

------------------------------------------------------------------------

# 28. Konsistensi di Atas Kebaruan --- TERKUNCI

When choosing between:

A. an impressive image that looks unrelated to previous NexaMOS images;

and

B. a slightly simpler image that strongly belongs to the NexaMOS system;

choose **B**.

The purpose of the visual language is cumulative brand recognition.

Each new asset should strengthen the same visual memory.

------------------------------------------------------------------------

Variasi diperbolehkan melalui:

-   different hero mechanisms;
-   different camera perspectives;
-   different network densities;
-   different primitive combinations;
-   different spatial structures;
-   different levels of abstraction.

Yang harus tetap konsisten:

-   palette;
-   system logic;
-   editorial technology aesthetic;
-   semantic primitives;
-   dark environment;
-   restrained glow;
-   conceptual clarity;
-   one-image-one-idea principle.

# 30. Keluarga Visual yang Direkomendasikan

To prevent monotony, NexaMOS may use several families inside the same
language.

## Family A --- System Objects

Best for: - CRM; - architecture; - automation; - integrations; - data
infrastructure.

Characteristics: - dimensional structures; - connected modules; -
rings; - data flows.

## Family B --- Entity & Lifecycle

Best for: - lead; - prospect; - opportunity; - customer; - journey; -
qualification.

Characteristics: - nodes; - filters; - gates; - state transformations.

## Family C --- Intelligence

Best for: - analytics; - market intelligence; - AI; - signal
processing; - insight.

Characteristics: - many signals; - convergence; - pattern emergence; -
computational layers.

## Family D --- Strategic Choice

Best for: - positioning; - competition; - strategy; - category; - value
innovation.

Characteristics: - paths; - territory; - branching; - constraints; -
selection.

All four families MUST remain inside the same NexaMOS universe.

# 31. Alur Produksi Gambar

Alur kerja yang direkomendasikan:

`ARTICLE → CORE IDEA → VISUAL BRIEF → NEXAMOS GRAMMAR → AI GENERATION → CURATION → BRAND QA → CROP/EXPORT → WEBSITE`

Urutan detail:

1.  Read the article or editorial brief.
2.  Reduce it to one dominant visual proposition.
3.  Select NexaMOS primitives.
4.  Define movement/state transformation.
5.  Assign semantic colors.
6.  Select a visual family.
7.  Generate the hero image.
8.  Reject generic AI results.
9.  Refine composition and simplify.
10. Verify thumbnail readability.
11. Add authentic logo/text afterward only if channel requires it.
12. Export optimized website formats.
13. Maintain article-image metadata and accessibility information in
    implementation.

# 32. Catatan Implementasi Web untuk Coding Agent

When implementing NexaMOS editorial imagery:

-   preserve a high-resolution source;
-   generate optimized responsive image variants;
-   prefer modern formats such as WebP/AVIF where the stack supports
    them;
-   preserve an appropriate fallback when required;
-   define intrinsic width/height or equivalent to minimize layout
    shift;
-   use meaningful alt text based on the image's actual conceptual
    content;
-   do not keyword-stuff alt text;
-   use descriptive filenames where practical;
-   ensure article structured data and social metadata reference the
    correct hero image where applicable;
-   support large image previews;
-   do not place important image content too close to crop-sensitive
    edges;
-   maintain a safe central composition for responsive cropping.

If implemented in Next.js, use the project's image optimization
architecture appropriately rather than bypassing it without reason.

# 33. Prinsip Aksesibilitas

Identitas visual tidak boleh membuat makna bergantung sepenuhnya pada warna.

State differences SHOULD also be communicated by:

-   position;
-   form;
-   connectivity;
-   illumination;
-   direction;
-   boundaries;
-   labels outside the generated illustration when necessary.

Alt text should describe the meaningful concept, not list decorative
visual effects.

Example:

Bad:

> "Green blue futuristic NexaMOS image."

Better:

> "Illustration of an offline customer conversion sending a server-side
> data signal back to an advertising platform."

# 34. Integritas Editorial

Visuals MUST support the content rather than manufacture false drama.

Do not:

-   depict fabricated statistics;
-   imply an integration exists when the article only discusses a
    concept;
-   create fake screenshots and present them as real NexaMOS UI;
-   depict fake customer results as factual;
-   use misleading logos or endorsements;
-   create a visual claim stronger than the article evidence.

Ilustrasi konseptual harus tetap jelas sebagai ilustrasi konseptual.

# 35. Formula Khas NexaMOS

Ekspresi paling ringkas dari sistem visual NexaMOS adalah:

> **Dark System + Nexa Gradient + Semantic Nodes + Information Flow +
> Circular Intelligence + One Dominant Idea**

Or operationally:

`ENTITY + SIGNAL + STATE + FLOW + DECISION + FEEDBACK`

Tidak setiap gambar membutuhkan keenam elemen.

Gunakan hanya primitif yang diperlukan untuk menjelaskan ide dominan.

# 36. Prinsip Desain Kanonis --- TERKUNCI

Prinsip-prinsip berikut bersifat kanonis:

1.  **Membuat sistem pemasaran yang tak terlihat menjadi terlihat.**
2.  **One Image = One Idea.**
3.  **Nexa gradient represents information in motion.**
4.  **Circular geometry represents system/feedback/learning.**
5.  **Node represents an entity.**
6.  **State transformation represents lifecycle progression.**
7.  **AI is a computational layer, not a robot.**
8.  **CRM is a relationship/state network, not an address book.**
9.  **Strategy is choice, not decoration.**
10. **Intelligence emerges from signals and patterns.**
11. **Dark environment is the default signature canvas.**
12. **Consistency beats novelty.**
13. **The image should communicate the mechanism, not merely the
    industry.**
14. **Logo repetition is not a substitute for visual identity.**
15. **NexaMOS visual assets should look editorial, technological,
    systematic, and premium.**

# 38. Governance dan Versioning

This document is **NexaMOS Visual Language Bible v1.0**.

Future changes SHOULD be versioned rather than silently rewriting
canonical principles.

Recommended version behavior:

-   `v1.x` = refinements without changing the core visual philosophy;
-   `v2.0` = major change to the visual system or art direction.

Agents SHOULD distinguish between:

-   **canonical rule**;
-   **working approximation**;
-   **experiment**.

Current approximate HEX values are working values until verified against
official vector/source brand specifications.
